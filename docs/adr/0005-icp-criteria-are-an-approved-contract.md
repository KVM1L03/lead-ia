# ICP Criteria are a user-approved contract, not a rendering of the prompt

Preflight shows the criteria a run will judge businesses against. Those criteria could be a display artifact — the model restating its understanding while qualification keeps working off the raw prompt — which costs nothing and risks no regression, but produces a screen that can disagree with the verdicts it precedes. We chose the opposite: `PromptToQuery` emits the criteria, the user edits and approves them at Preflight, and the approved list travels into `QualifyLead` as the checklist it must report on key by key, replacing the free-form `icp_fit` keys the model invents today. Qualification semantics therefore change, `icp_fit` becomes stable across leads in a run (and comparable across runs), and the qualifier evals have to be re-baselined before this merges — which is also what makes the decision expensive to reverse once the eval suite is retuned around it.
